# v4.4a 受信トレイ：実装記録（2026-10-10）

配布ファイル：[`dist/自計化レビュー_v4.4a_受信トレイ.html`](../dist/自計化レビュー_v4.4a_受信トレイ.html)
土台：v4.3（`base/jikeika-review-v4.3.html`。中身は変えていません）

## 1. 何ができるようになったか

freee から出力したCSVを、資料ページにまとめてドロップする（または「CSVをまとめて選ぶ」で選ぶ）と、**受信トレイ**が開きます。受信トレイでは、反映する前に次のことを確かめられます。

| 確かめること | 表示の例（架空データ） |
|---|---|
| 資料の種類・切り口・期間・件数 | `bs-party-2026.csv`　月次BS（月末残高）（取引先別）　2026/01〜2026/12　741セル・円 |
| 前回との違い | 「反映する：更新」　追加 2行・削除 1行（変わった月：2026/01）<br>事業主貸　2026/01　借方　+1,000円 |
| 帳票の金額の違い | 金額が変わったセル 2・新しいセル 0・なくなったセル 0<br>現金　2026/01　前回 47,800　今回 47,801　差 +1円<br>現金／未選択　2026/01　前回 47,800　今回 47,801　差 +1円 |
| 変更なし | 「変更なし」読込済みの仕訳と中身がすべて同じです（ファイル名や出力日時だけの違い） |
| 重複 | 「重複」bs-item-2026.csv と同じ内容のため、反映しません |
| 不足 | まだない基本資料：前期の仕訳帳、当期の月次BS、当期の月次PL |
| 別の会社のCSV | 「反映できない」読込済みの帳票と事業者名が違います（読込済み：A／このCSV：B） |
| 再確認に戻る記録 | 反映すると、確認済みの記録 3件が「再確認」に戻ります |

確認したら、「反映するCSVは、すべて『会社名』の資料です」にチェックを付けて「N件を反映」を押します。利用者の入力は、このチェック1つだけです。

反映後は結果の画面が出ます。ほかの操作をする前なら「反映前に戻す」で、資料と確認の記録を反映前に戻せます。

## 2. 仕様（①〜⑦）

| 項目 | 内容 |
|---|---|
| ①検出・動作の条件 | 種類を指定せずに入れたCSV（ドロップ、「CSVをまとめて選ぶ」）は受信トレイへ。種類を指定したボタン（「CSVを追加」など）と、デモの会社は従来の画面のまま。<br>1ファイルごとに、v4.3 と同じ手順（文字コード、見出し、種類、当期／前期、帳票の年度・単位・表示方法）で判定する。<br>**自動で反映するのは**：当期の仕訳帳、前期・過去の仕訳帳、freee の当期の月次BS・PL（v4.3 の自動連続取込と同じ条件：円・単月・読取エラーなし・切り口が1つ・年度と事業者名が確定）。<br>**それ以外は「要確認」**：期日一覧・残高一覧・前期のBS／PL・千円や累計の帳票・読取エラーがあるCSV・期間が合わないCSV。行の「1ファイルずつ確認して読み込む」で従来の画面を開く。 |
| ②表示する根拠 | ファイル名、判定した種類と切り口、期間、件数（行・セル）、単位、文字コード、判定の理由、前回との違い（仕訳：追加・削除の行数、変わった月、科目×月×借方／貸方の合計の増減を大きい順に8件。帳票：変わったセル・新しいセル・なくなったセルの数と、科目／内訳×月の前回・今回・差を大きい順に8件）。 |
| ③利用者への説明 | 「変更なしのCSVは反映しないため、記録に影響しません」「反映すると、確認済みの記録 N件が『再確認』に戻ります（1ファイルずつ読み込む場合と同じ動きです）」など、画面の文で説明する。 |
| ④次の行動 | 反映する／外す／1ファイルずつ確認して読み込む／不足資料を freee から出して追加する／反映前に戻す。 |
| ⑤誤動作を防ぐ条件 | ・**変更なし**：同じファイル（指紋が同じ）か、中身が同じ（仕訳は30項目、帳票は月・科目・内訳・期首と金額で比べる。行番号・列の位置・ファイル名・出力日時は使わない）なら反映しない。<br>・**重複**：受信トレイの中で中身が同じCSVは、2つ目以降を反映しない。<br>・**同じ種類が2つ**（例：当期の仕訳帳が2つ）は、1つを外すまで反映できない。前期の仕訳帳は複数を追加できるが、同じ日付・仕訳番号が重なると止める。<br>・**事業者名**：読込済みの帳票と違う、または受信トレイの帳票どうしで違うと反映しない。会社の設定名と違うだけのときは、会社の確認と一緒に1回だけ確かめ、同じ事業者名なら次回からは聞かない。<br>・**帳票の期間**：受信トレイのBS・PLで期間がそろわないと「要確認」。<br>・**途中で失敗**したら、その受信トレイからの反映をすべて取り消して反映前に戻す（一部だけ反映された状態を残さない）。<br>・「1ファイルずつ確認する（従来の方法）」でも、変更なし・重複のCSVは渡さない。<br>・反映は v4.3 の取込処理（`commitImport`）をそのまま使う。保存されるデータの形は、1ファイルずつ読み込んだ場合と同じ（テストで一致を確認）。 |
| ⑥必要な権限・データ | 追加の権限・通信・入力はなし。基本資料（当期・前期の仕訳帳、当期の月次BS・PL）。タグ別のBS・PL（取引先・品目・部門）も同じ受信トレイで扱う。 |
| ⑦処理を軽くする方法 | 判定は1ファイルずつ順に行い、5,000行以上は v4.3 と同じ Worker で集計する。比較は Map を使った1回の走査。反映は既存の取込処理を1ファイルずつ呼ぶ（v4.3 の自動連続取込と同じ）。 |

### 戻す仕組みについて

- 反映の直前に、会社の保存データ（資料と確認の記録）の写しを**メモリにだけ**1世代残します。ブラウザ内の保存データやバックアップには入れません（大きさが倍にならないように）。
- 反映後に記録が保存される操作（メモ、状態の変更、会社の切り替えなど）をすると、写しは捨てます。後から行った記録を、戻す操作で消さないためです。
- ページを閉じると戻せなくなります。必要ならバックアップから復元してください。
- 消費税区分チェックに渡した仕訳帳は、戻す操作では戻りません（結果の画面に表示します）。

### 4.2 処理時間（`node tests/perf-inbox.js 25 100`、参考値）

| 規模 | 受信トレイの判定 | 受信トレイの反映 | 従来の画面での取込 | 入れ直し（変更なし）の判定 |
|---|---|---|---|---|
| 25倍（仕訳 5,025行） | 0.6秒 | 2.9〜3.1秒 | 3.0〜3.2秒 | 0.5秒 |

## 5. 確認していないこと

- 実際の仕訳帳CSV（受け取っていないため）。
- 12MBに近いCSV、11ファイル以上を入れた場合の表示（上限の判定はコードで確認しただけ）。
- 千円・累計の帳票、前期のBS・PL、残高一覧が「要確認」になること（v4.3 の判定をそのまま使っているが、受信トレイでは未実行）。
- 消費税区分チェックへの受け渡しの結果表示（テスト環境では区分チェックの読込状況まで確認していない）。
- 印刷、キーボードだけでの操作、画面読み上げ。

## 6. 旧版へ戻す方法（データを保ったまま）

- 保存データの形を変えていないので、**v4.3 のHTML（`base/jikeika-review-v4.3.html` または手元の v4.3）を開けば、そのまま使えます**（4.1 の11で確認）。
- 受信トレイで反映した内容だけを取り消すには、反映直後の「反映前に戻す」、またはバックアップの復元を使います。

## 7. このあと

- 受信トレイの「前回との違い」は、いまは**資料の単位**です。設計書の S1（論点キーと指紋）を実装すると、「変わった論点だけ再確認」にでき、変更があったときも、関係しない確認の記録を残せます。
