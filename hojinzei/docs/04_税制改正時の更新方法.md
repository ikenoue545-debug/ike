# 税制改正時の更新方法

税率・金額基準・適用期限は `backend/taxengine/rules/data/*.json` に、ルールごと・版ごとに保存しています。過年度の申告を当時の内容で計算し直せるよう、**版は削除せず追加**します。

## 1 改正の内容を一次資料で確認する

- 国税庁「法人税関係法令の改正の概要」（毎年5月ごろ）、法令（e-Gov）、通達、別表の記載要領。
- 適用時期の基準を確認します：事業年度開始日（例：税率、防衛特別法人税）、終了日（例：様式の版）、支出日（例：交際費等から除く飲食費の基準）など。

## 2 ルールの版を追加する

例：中小企業者等の法人税率の特例（租税特別措置法第42条の3の2）が延長された場合。

1. `corporate_tax_rate.json` の `"version": "2027-04"`（現在は `status: "unverified"`）を、確認した内容で書き換えるか、期間を分けて版を追加します。
2. 各版に次を入れます。

```json
{
  "version": "2027-04",
  "valid_from": "2027-04-01",
  "valid_to": "2029-03-31",
  "applies_to": "普通法人（通算法人を除く）",
  "conditions": "…（何を確認したか、条件）",
  "values": { "standard_rate": "0.232", "sme_rate": "0.15", "…": "…" },
  "sources": [{ "title": "令和9年度 法人税関係法令の改正の概要（国税庁）", "url": "https://…", "provisions": "措法42の3の2", "checked": "…" }],
  "status": "source_checked",
  "checked_by": "確認した人",
  "checked_at": "2027-05-30",
  "expert_review": "未"
}
```

- 税率は文字列（`"0.15"`）、金額は整数円で書きます（浮動小数点を使わないため）。
- 適用期間は重ならないようにします（重なると読み込み時にエラー）。
- 内容を確認できていない版は `status: "unverified"` のままにします。その版を使う事業年度は重大エラーになり、承認できません。
- 制度の対象外の期間は `status: "not_applicable"`（例：防衛特別法人税の創設前）。

## 3 様式が変わった場合

- `return_forms.json` に新しい様式の版を追加します（基準は事業年度終了日）。
- 行番号・計算式が変わった別表は `backend/taxengine/schedules/` のモジュールを直します。行番号は様式の PDF と記載要領で確認します。
- 旧様式の年度も扱う必要があれば、旧様式用の分岐を残します（現状、令和8年3月31日以前終了の様式は未対応＝重大エラー）。

## 4 テストを足して流す

```sh
cd hojinzei/backend
.venv/bin/python -m pytest -q
```

- `tests/test_engine_cases.py` に、改正後の事業年度の事例と、改正前後の境目（開始日が前日・当日）を足します。期待値は手計算でコメントに残します。
- `tests/test_engine_units.py` の `test_rule_selection_by_basis` に、版の選択を足します。
- 既存の回帰テスト（`tests/golden/`）が変わったら、変わった理由を確認します。意図した変更のときだけ `UPDATE_GOLDEN=1` で作り直し、差分をレビューしてからコミットします。

## 5 専門家の確認を記録する

画面「税率・法令」で、レビュー担当者・管理者が「専門家の確認を記録」から、確認した人・内容を記録します（`rule_reviews` テーブル）。

## 6 承認済みの年度への影響

承認時の計算結果（`return_snapshots`）には、使ったルールの版と入力のハッシュを保存しています。ルールを追加しても、過去の承認済みの結果は変わりません。最終チェックの画面で「承認後に入力が変わっています」と出た場合は、承認を取り消して確認し直します。
