# 記帳レビュー v0.1

会計事務所の担当者が、freee で記帳したあとの確認を「どの取引を・なぜ・何と照合し・どう対応するか」まで追えるようにするレビューアプリです。
ブラウザで開くだけの1ファイルで、**外部と通信せず、freee の帳簿も変更しません**。

同じリポジトリの「自計化レビュー」（月次BS・PL中心）とは別のアプリで、互いのデータ・コードには触れません。

## 起動

1. [`dist/記帳レビュー_v0.1.0.html`](dist/記帳レビュー_v0.1.0.html) をダウンロードし、ブラウザ（Chrome・Edge）で開く。インストールやサーバーは不要です。
2. 最初の画面で **「サンプルデータで試す」** を押すと、架空の会社（6か月分の仕訳、正常な取引と問題候補の両方を含む）でレビュー一覧が開きます。

## 使い方（毎月の流れ）

| 手順 | 画面 | 内容 |
|---|---|---|
| 1 | 上部 | 会社を選ぶ（初回は「＋会社を追加」）。担当者名を入れる（更新履歴に残ります） |
| 2 | データ取込 | freee の［会計帳簿］→［仕訳帳］のCSVを選ぶ。**対象月だけでなく前3か月以上も**取り込むと、過去の処理と比較できます。取込前に、文字コード・読み取った列・借方貸方の合計・**読めなかった行と理由**を確認します |
| 3 | レビュー一覧 | 対象月を確認して「レビューを実行」。重要度順に確認事項が並びます |
| 4 | レビュー一覧 | 確認事項を選び、対象の取引・比較対象・計算の過程・推測・確認すべき資料・次の対応を読む。状況（未確認／確認中／先方確認待ち／修正済み／問題なし）とメモを記録する |
| 5 | 明細との照合（任意） | 通帳・カード明細・現金出納帳のCSVを、帳簿の口座科目と突き合わせる。一致以外がレビュー一覧に加わります |
| 6 | 引継ぎ | 未解決の確認事項を、テキスト・CSV・印刷で上席へ渡す |
| 7 | 翌月 | 翌月分のCSVを取り込んで実行。会社ルール・確認済みルールはそのまま使われ、前月以前の未解決は「繰越」として一覧に出ます |

freee で帳簿を直したあとは、同じ月のCSVを取り込み直して再実行します（その月の行を置き換えるので二重になりません。対応状況とメモは引き継がれ、検出されなくなった指摘には「再実行で検出されず」と付きます）。

## 実装済みの機能

### チェック（すべてプログラムによる再現可能な計算。同じ入力なら同じ結果）

| チェック | 何を見るか | 根拠の種類 |
|---|---|---|
| 重複候補 | 科目・金額・取引先（なければ摘要）が同じで、日付が近い仕訳。決済経路が違う二重計上（カード同期＋手入力など）も拾う | データ上の一致・不一致 |
| 勘定科目の不一致 | 同じ取引先（なければ同じ摘要）の過去の科目（3件以上・80%以上）や、会社ルールとの違い | 過去傾向／ルール |
| 税区分の不一致 | 同じ取引先・同じ科目の過去の税区分や、会社ルールとの違い。**その会社の納付税額に影響するか**を課税の状況から表示 | 過去傾向／ルール |
| 定期取引の計上漏れ | 前3か月は毎月あるのに対象月にない取引。会社ルールに登録した定期取引 | 過去傾向／ルール |
| 金額の違い | 定額だった取引の金額変更、過去の範囲を大きく超える金額、会社ルールの許容範囲外 | 過去傾向／ルール |
| 摘要・取引先の不足 | 取引先・摘要とも空欄の損益取引 | 資料不足による確認依頼 |
| 税区分と制度の適用時期 | インボイス経過措置の控除割合（控80・控70…）と取引日。国税庁の資料を出典として表示 | ルール（制度） |
| 現金残高 | 期首残高（会社ルール）からの日次残高のマイナス。期首残高が未登録なら断定せず確認依頼にする | データ／資料不足 |
| 明細との照合 | 一致／差額あり／片側のみ／同一取引か要確認。日付のずれ、合算・分割（2〜4件）、手数料程度の差額に対応 | データ／資料不足 |

### 過剰な指摘を避けるしくみ

- 口座どうしの仕訳（ATM引出し、カード代金の引落しなど）は振替として扱い、重複候補にしません。
- 過去も毎月同じ形で複数計上されている取引（例：同額の駐車場2区画）は、通常の処理とみなして外します。**外した候補と理由は一覧の上部で確認できます。**
- 経過措置の控除割合が時期どおりに切り替わった場合（控80→控70）は、税区分の不一致にしません。
- 科目が変わっただけの取引は「計上漏れ」と「科目の不一致」に二重に出しません。
- 判定に必要なデータがないとき（過去の月がない、税区分の列がない、期首残高がない等）は、判定せずにその旨を表示します。

### 確認事項に表示する内容

重要度・状況／対象取引（日付・金額・取引先・科目・税区分・**元CSVのファイル名と行番号**）／指摘理由（事実）／比較対象／判定条件と計算／**推測（事実と別の欄）**／消費税への影響／確認すべき資料／次の対応／修正案（判断できる範囲だけ。できないときは理由）／出典／freee で探すときの条件／質問文案（定型文）／担当者メモ・確認者・更新履歴

### 会社別ルール（会社ごとに別々に保存）

事業内容・決算月・消費税の処理方針／取引先ごとの通常の科目・税区分／毎月発生する取引と許容範囲／重要性基準／現金の期首残高／科目の種類（口座・貸借・損益）／特有の取引のメモ／**確認済みルール**

確認済みルールは「この会社・このチェック・この条件（取引先・科目・語句・金額のいずれか必須）・この期間」に限定して登録します。当たった指摘は消さずに「問題なし（確認済みルール）」と表示します。

## 未対応（この版では動きません）

| 項目 | 状況 |
|---|---|
| freee API・ブラウザ拡張による取込 | 未実装（CSVのみ）。比較と次の段階は [`docs/連携方式の比較.md`](docs/連携方式の比較.md) |
| 登録経路（自動登録ルール・明細同期・手入力）の取得 | 仕訳帳CSVに含まれないため未取得。自動登録ルールに関する記述は「推測」と表示 |
| freee の該当画面へのリンク | 設けていません（CSVに取引IDがなく、公式に確認できたURL形式もないため）。検索条件のコピーで代替 |
| 売上資料・請求書と売上・入金、給与資料と給与・預り金の照合 | 未実装（口座の明細と帳簿の照合のみ） |
| 売掛金・買掛金・仮払金などの滞留、役員貸付金・借入金、期首・期末残高の整合性 | 未実装 |
| 前月比・前年同月比、売上区分別の変動 | 未実装（月次BS・PLは「自計化レビュー」側にあります） |
| AIによる摘要の解釈・説明・文案作成 | 未実装。質問文案は定型文です。顧客データを外部へ送る同意と範囲を決めてから追加する想定 |
| 複数人での同時利用・データ共有 | 未対応（保存はそのブラウザの中だけ）。受け渡しはバックアップ（JSON）で行います |
| 仕訳帳CSVの列 | freee の公式ヘルプが自動取得できず、列名は既存アプリが対応している新・旧形式の名前から設定しています。実際のCSVで「使わなかった列」「読めなかった行」を取込前に必ず確認してください |

## データの扱い

- 保存先：このパソコンのこのブラウザの IndexedDB（`kicho-review`）。会社ごとに別レコードで、必ず会社IDを指定して読み書きします。
- 外部送信：なし。配布ファイルは Content-Security-Policy で通信を禁止しています（`connect-src 'none'`）。
- 削除：「データと安全性」から、会社単位または全件を削除できます。バックアップ（JSON）の保存・復元もここです。
- 取り込んだ文字列は表示するだけで、命令として解釈しません（画面には必ずエスケープして出します）。

## 開発

```sh
npm test            # 判定エンジンのテスト（Node のみで動く）
npm run test:ui     # dist を作り、Chromium で取込→レビュー→保存→再読込→照合→引継ぎを通す（Playwright）
npm run build       # dist/記帳レビュー_v0.1.0.html を作る
npm run sample      # samples/ にサンプルCSVを書き出す
```

| パス | 内容 |
|---|---|
| `src/core/` | 判定エンジン。画面に依存せず Node でも動く（`csv` 取込と検証、`model` 科目の種類・制度ルール表、`checks` 取引単位のチェック、`reconcile` 照合、`review` 状態・確認済みルール・引継ぎ、`sample` サンプルデータ） |
| `src/ui/` | 画面（`store` IndexedDB、`app` 画面、`app.css`） |
| `samples/` | 架空のサンプルCSV（仕訳帳2ファイル、普通預金明細、読めない行を含む例） |
| `tests/` | `core.test.js`（15件）、`ui-flow.js`（画面の通しテスト） |

サンプルデータはすべて架空です。顧客の実データはリポジトリに入れないでください。
