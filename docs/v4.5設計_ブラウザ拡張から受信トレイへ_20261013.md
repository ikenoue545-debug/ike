# v4.5 設計：freee のCSVを、拡張機能から受信トレイへ送る（設計のみ）

2026-10-13。実装は別途指定する範囲で行います。前提は、v4.4a の受信トレイ（[実装記録](v4.4a_受信トレイ_実装記録_20261010.md)）と、v4.4 設計書の F00（論点キー・指紋）です。

## 0. 使う前の条件（設計の前提）

- **顧問先の了承を得ていること**（了承済みとの連絡を受けています）。了承の日付と範囲（読み取りだけ、帳票の種類）は、利用者が拡張機能に1回記録します。
- **見えない動作はしない**。freee の画面に「レビュー用の拡張機能が動作中」の表示を常に出し、取得した資料の一覧（名前・種類・時刻・件数）を、いつでも見られるようにします。記録を消す、通知を避ける、操作を隠す処理は作りません。
- **読み取りだけ**。freee へ書き込む操作（登録・更新・削除・承認）は作りません。
- **利用者が押したときだけ**動かします。定期的な自動取得はしません。
- **追加費用なし**。ストアに公開せず手元で読み込みます。外部サーバーとAPIは使いません。
- **freee の利用規約**：現行の規約に、自動操作・拡張機能を禁じる条項は見つかりませんでしたが、「認められている」ことも確認できていません。実装の前に、freee のサポートに書面（メール）で確認し、結果を記録に残します。禁止、または不明のままなら、方式Aを第一案にします（下記）。

## 2. 方式の比較

| | 方式A：観察型（推奨） | 方式B：代行型 |
|---|---|---|
| 動き | 利用者が freee で、自分でCSVの出力ボタンを押す。拡張機能は、そのダウンロードを検知して、受信トレイへ送る候補にする | 拡張機能が、freee の画面のボタンを押してCSVを出力する |
| 規約上の懸念 | 小さい（利用者の通常の操作に、取り込みの補助を足すだけ） | 大きい（画面の自動操作） |
| freee 画面の変更への強さ | 強い（ボタンの位置に依存しない） | 弱い |
| 利用者の操作 | 出力は手作業、以降はワンクリック | ワンクリック |
| 実現方法 | 後述（3.2） | ページ内で、出力ボタンの押下と、返ってくるCSVの取得 |

**推奨は方式Aです。** 方式Bは、freee の規約の確認が取れ、方式Aで足りない場合だけ検討します。

## 3. 仕様（方式A）

### 3.1 全体の流れ

1. 利用者が freee で、いつもどおりCSVを出力する（仕訳帳、月次BS・PL）
2. 拡張機能が、そのCSVを検知して「取得済み」の一覧に入れる（拡張機能の中だけに保存）
3. 利用者が「この会社をレビューへ送る」を押す
4. レビューアプリの受信トレイが開き、種類・期間・前回との違いを確認する（v4.4a の機能）
5. 利用者が確認して反映する。変更なしの資料は反映されない

### 3.2 ①〜⑦

| 項目 | 内容 |
|---|---|
| ①検出・動作の条件 | freee のドメインで、CSVのダウンロードが始まったとき（ダウンロード検知）。対象は、仕訳帳と月次推移のBS・PL。それ以外のダウンロード（請求書、領収書など）は拾わない。拡張機能のアイコンを押したときだけ、一覧と「送る」を表示する |
| ②表示する根拠 | 取得済みの一覧：ファイル名、判定した種類（受信トレイと同じ判定）、事業所名（CSVの本文から）、期間、件数、取得日時。送るときに付ける情報を、すべて画面で確認できる（§3.3） |
| ③初心者への説明 | 「freee でCSVを出力すると、ここに並びます。『レビューへ送る』を押すと、受信トレイで内容を確認できます」 |
| ④次の行動 | 取得済みを送る／外す／足りない資料（受信トレイの不足表示）を freee で出力する |
| ⑤誤判定を防ぐ条件 | 会社の取り違えを防ぐ（§3.3の事業所名・会社IDの確認）。拡張機能の中で内容は書き換えない。**取得できなかった**ときは、何も送らない。送った内容は、受信トレイが再度判定する |
| ⑥必要な権限・データ | 拡張機能の権限は最小限：freee のドメインと、レビューアプリのページだけ。Cookie・パスワード・ブラウザの履歴は読まない。ログイン情報は扱わない |
| ⑦処理を軽くする方法 | 取得は利用者の操作のときだけ。大きなCSV（12MB超）は取得しない（アプリ側の上限と同じ）。保存は、直近のものだけ（件数と期限を決める） |

### 3.3 送るデータの封筒（メタ情報）

| 項目 | 内容 |
|---|---|
| 会社ID（アプリ側） | 初回に、利用者が1回だけ「この事業所はこの会社」と対応づけて登録する |
| 事業所名・事業所ID | CSVの本文と、画面に表示された名前（取れる範囲） |
| 資料の種類、対象期間、件数 | 受信トレイと同じ判定を、事前に表示するだけ（確定は受信トレイ） |
| 取得元・取得日時 | 「拡張機能（ダウンロード検知）」、取得した日時 |
| 拡張機能の版、形式の版 | 後で原因を調べられるように |
| データの指紋 | CSVの内容だけから作る（受信トレイの「変更なし」判定と同じ考え方） |

- 事業所と会社IDの対応が、登録と違う、または事業所名が違うときは、送らずに理由を表示する。
- 指紋が前回と同じなら、「変更なし」と表示して、送らない。
- 同じデータを2回送っても、重複しない（受信トレイの重複判定）。

### 3.4 拡張機能とアプリの受け渡し

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| 1（推奨）| アプリの file:// ページへ、拡張機能がファイルを渡す（ブラウザの拡張機能の設定で「ファイルのURLへのアクセスを許可」が必要）。アプリ側は、受け取り口を新設（送信元の確認つき） | 保存データの場所（IndexedDB）が今のまま。移行不要 | 初回の設定が1つ要る |
| 2 | アプリを拡張機能の中に同梱して開く | 設定が不要 | 保存の場所が変わる。今のデータを、バックアップから移す必要がある |
| 3 | 取得したCSVを、フォルダに保存して、利用者が受信トレイへドロップ | 拡張機能とアプリが独立 | 手数が1つ増える |

- 受け取り口は、ページ内のメッセージの送信元（拡張機能のID）を確認し、想定外の送信元は捨てる。
- 受け取り口は、受信トレイの `receive` に、**ファイルとして渡すだけ**にする。反映の判断はすべて受信トレイが行う（v4.4a と同じ）。

## 4. 実装の段階

| 段階 | 作業 | 完了条件 |
|---|---|---|
| E0 | freee のサポートに、拡張機能の利用の可否を確認し、記録する。権限ごとの出力可否を、顧問先の画面で確認する | 確認結果を文書に残す。禁止・不明なら、E1以降は止める |
| E1 | アプリ側の受け取り口（送信元の確認、封筒の検証）と、受信トレイへの表示（取得元・取得日時・事業所の対応） | 架空データで、不正な送信元・別の会社・形式不正が、すべて取り込まれず理由が出る |
| E2 | 拡張機能の最小版：ダウンロード検知、一覧、了承の記録、「動作中」の表示 | 架空のページ（freee に似せたテスト用のページ）で、検知から受信トレイまで通る |
| E3 | 実際の freee 画面での確認（顧問先の了承のもとで、利用者が操作） | 件数と判定だけを記録する |

## 5. 検証計画

| 確認 | 期待 |
|---|---|
| 別の会社のCSV | 事業所名・会社IDが合わず、取り込まれない。理由を表示 |
| 対象期間が違う | 受信トレイが「要確認」にする |
| 一部だけ取得できた | 何も送らない |
| 同じデータを2回送る | 2回目は「変更なし」。確認済みの記録が変わらない |
| 手動のCSV取込との一致 | 同じ内容なら、変換後のデータと指紋が一致 |
| 拡張機能なし | 従来の取込・受信トレイがそのまま動く |
| 想定外の送信元 | 捨てる。ログに残す |
| バックアップ・復元、v4.3 との互換 | 保存データの形を増やさない（取得元の情報は受信トレイの表示のみ） |
| freee の画面・出力形式の変更 | 検知しなくなるだけ。手動取込に案内する |
| 通信 | freee と、利用者のパソコンの間だけ。外部への通信の呼び出しが増えていない（コードの検索で確認） |
| 追加費用 | 発生しない（ストア登録・サーバー・有料サービスなし） |
| 透明性 | 「動作中」の表示が常に出る。取得の一覧が見られる。利用者の操作なしに取得しない |
